# Мерцание объёмного тумана в fog_spot_test — отчёт для Fable

Дата отчёта: 2026-09-06. Диагностика выполнена 2026-09-05.
Статус: воспроизведено, причины локализованы переключением отдельных функций; исправлений в коде нет.

## Симптом и результат

Пользователь отметил две зоны на карте `data/levels/fog_spot_test.json`:

1. Верхушка светового конуса: яркость и форма небольшого участка дрожат при неподвижной камере.
2. Дальний край пола слева от конуса: над границей геометрии появляется тёмное размытое пятно, которое мерцает.

Это два разных проявления объёмного тумана. Отключение `atmosphere.jitter` резко снижает колебания верхушки, но оставляет дефект у пола. Отключение `atmosphere.conservativeDepth` убирает тёмное пятно, но сохраняет колебания верхушки. Комбинация убирает пятно и сильно снижает мерцание конуса. Это диагностический обход, не готовое исправление.

Для отдельных A/B-прогонов добавить один из аргументов и сменить имя `--shot`:

```text
--set=atmosphere.conservativeDepth:0
--set=atmosphere.jitter:0
"--set=atmosphere.jitter:0;atmosphere.conservativeDepth:0"
```

Названия CLI здесь именно `atmosphere.*`; размер сетки задаётся отдельно через `fog.gridPixels`.

## Локализация в коде

### 1. Тёмное пятно у пола

`shaders/fog_scatter_cs.hlsl`, строки 254–261: читается один HZB texel по `coord.xy`; если геометрия ближе near-face ячейки, в `FogScatter[coord]` записывается ноль.

Далее интегрированный объём фильтруется по XY, поэтому ячейка влияет также на соседние экранные лучи. На границе пола и неба одноклеточное отсечение не учитывает всю область влияния фильтра: обнулённый столбец уменьшает накопленное рассеяние в соседних пикселях неба. Смещение near-face на −0.5 слайса защищает по Z, но не даёт необходимого запаса по XY. Это объяснение по коду согласуется с исчезновением пятна при conservativeDepth=0; отдельного GPU readback ячеек не делалось.

Также проверить:

- Строки 288–292 того же шейдера: история проверяется по одному прошлому HZB texel, хотя сама история читается трилинейно.
- `shaders/fog_common.hlsli`, `FogVolumeSampleAt`: фильтрованное чтение интегрированного объёма.
- `sources/rendering/core/Renderer.cpp`, создание размеров fog/HZB: сетка fog округляется вверх, HZB имеет собственное округление mip-размеров. Нельзя без проверки считать `coord.xy` точным совпадением покрываемой области при любом разрешении.

Направление исправления: учитывать полный XY footprint фильтра при отсечении и корректно обращаться с обнулёнными соседями истории. Проверить отображение fog-grid ↔ HZB, включая DLSS и нечётные размеры. Простое отключение оптимизации маскирует дефект, но не исправляет алгоритм.

### 2. Дрожание верхушки конуса

`sources/app/scene/SceneRenderer_Lighting.cpp`, строки 549–555: при валидной истории точка внутри ячейки меняется по Halton 2/3/5 каждый кадр.

`shaders/fog_scatter_cs.hlsl`:

- `FogSampleCell`, примерно строки 185–220: освещение спота зависит от положения выборки, расстояния, углового затухания, soft fading и тени. Размеры для distance bias/soft fading также вычисляются от jittered positions.
- Строка 303: четыре выборки применяются только при отсутствии истории; обычный кадр с историей получает одну выборку.
- Строки 309–318: jittered результат смешивается с историей с весом 0.9.

Вблизи вершины световой вклад сильно меняется внутри крупной ячейки, и одна выборка оставляет временные колебания после накопления. A/B с jitter=0 подтверждает зависимость от этого пути. Вклад отдельных составляющих (угловое затухание, радиус bias, тень) пока не разделён дополнительными экспериментами.

Направление исправления: проверить стабильный расчёт размера ячейки и фильтрацию/несколько выборок локального света в областях большого градиента, сохранив пользу temporal jitter. Просто увеличить historyWeight — риск шлейфов; просто выключить jitter — риск более заметной сетки при движении. Конкретный алгоритм исправления ещё не выбран и не проверен.

## Что проверить после исправления

1. Повторить тот же ракурс и серии с jitter=true, temporal=true, historyWeight=0.9, conservativeDepth=true. Тёмного ореола над полом быть не должно; колебания вершины должны существенно снизиться относительно `auto_*`.
2. Сравнить исправленное отсечение с conservativeDepth=0: на границах геометрии/неба оптимизация не должна создавать пятна.
3. Проверить движение камеры, силуэты столбов, появление новой области кадра и сброс истории: нет шлейфов, провалов тумана и заметного скачка качества.
4. Проверить DLSS Balanced и native, fog.gridPixels=8/16/32, нечётные размеры окна, Legacy и VSM.
5. Скомпилировать затронутые шейдеры через `python tools/check_shaders.py fog`, расширить проверку при изменении общего include; проверить GPU validation и стоимость fog-пасса до/после.
6. Соблюдать CRLF и правила session logging. Диагностические события писать в session log, не добавлять отдельный файл событий.

## Ограничения выполненной диагностики

Исходники и настройки уровня не изменены. Исправления, проверки движущейся камеры, GPU validation и замеры стоимости не выполнялись. Отдельные A/B-серии имеют разные фазы Halton/DLSS и включённую автоэкспозицию, поэтому малые отличия чисел не следует трактовать как изолированный эффект одной операции.

Захваты всех серий завершились успешно, но запущенные диагностические процессы оставались живы после последнего снимка без footer `session end: clean shutdown`; они были принудительно остановлены по своим PID. Эти прогоны подтверждают изображение и локализацию, но не являются успешным тестом штатного завершения приложения. Причина зависания завершения отдельно не исследовалась.

## Исправление (Fable, 2026-09-06)

Статус: **исправлено**, серии сняты тем же рецептом (12 снимков одного процесса, та же поза, DLSS balanced), метрика
и регионы — из этого отчёта; исходная серия `auto_*` воспроизведена на тех же PNG (0.560/13, 0.205/28).

| Серия | Верхушка: σ / max размах | Край пола: σ / max размах |
| --- | ---: | ---: |
| `auto_*` (до) | 0.560 / 13 | 0.205 / 28 |
| после, `samplesPerCell 1` | 0.564 / 17 | 0.118 / 10 |
| **после, дефолт (`samplesPerCell 2`)** | **0.280 / 7** | **0.108 / 9** |
| после, `samplesPerCell 4` | 0.246 / 6 | 0.112 / 11 |
| `stable_*` (jitter 0 + cull 0, ориентир) | 0.090 / 3 | 0.114 / 10 |

1. Пятно у пола: `FogTileFarthest` в `shaders/fog_scatter_cs.hlsl` — самая дальняя глубина по 3×3 тайлам на mip'е сетки
   (XY-footprint трилинейного фильтра), и для текущего отсечения, и для проверки истории по прошлому HZB. Ориентир UE —
   `GenerateConservativeDepth.usf`, `ComputeFroxelCullRect(…, FootprintMargin 0.5)`. Край пола вышел на уровень
   «отсечение выключено», пятно исчезло визуально (`scratchpad/flk_edge_before_after.png`).
2. Верхушка: радиусы ячейки для distance bias / soft fading считаются от неджиттерного центра; новая ручка
   `samplesPerCell` (JSON уровня, `--set=atmosphere.samplesPerCell`, Inspector «Samples Per Cell»), дефолт 2 =
   антитетическая пара (offset, 1−offset). Стоимость fog-пасса на этой сцене 0.099 → 0.103 мс (4 выборки: 0.115).
3. Остаток верхушки (0.28 против 0.09 без джиттера) — одиночный тап тени спота в джиттерной точке; не трогал.
4. Зависание процессов после последнего снимка не воспроизвелось: все серии завершились `session end: clean shutdown`
   (снимались с `--wind-freeze`, как требует фазовая серия; в отчёте было `--wind-freeze=0`).
