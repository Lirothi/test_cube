# Локальная модель в редакторе: команды естественным языком (WITH_EDITOR)

Цель: набрать «зарой все пальмы» и получить выполненную команду редактора с откатом по Ctrl+Z.
Только `WITH_EDITOR`; в Release-билде не должно остаться ни кода, ни зависимостей, ни файлов модели.

## Почему грамматика НЕ решает задачу (зафиксировано сразу, чтобы не вернуться)

Первая идея была «глагол + квантор + строка в `MatchesSearch`», без всякой модели. Она ломается
на ПЕРВОМ же примере: ассеты зовутся `coconut_palm` / `date_palm` / `curly_palm`, а поиск ищет
подстроку — русское «пальмы» не совпадёт ни одной буквой. Грамматика покрывает ровно то, что
и так набирается в поиске аутлайнера. **Семантика ИМЕНИ — это и есть задача, а не разбор фразы.**

Грамматика остаётся в плане, но НЕ как первый шаг, а как быстрый путь для точных формулировок (E7).

## Выбор модели

Задача узкая: текст → JSON с выбором из ~10 действий и ~124 имён ассетов. Нужны два свойства:
**русский язык** и **структурированный вывод**. Размер здесь даёт мало: выбор из списка,
поданного в промпт, 7B делает практически идеально, и 32B заметно лучше не будет.

| модель | Q4_K_M | где уместна |
|---|---|---|
| Qwen2.5-7B-Instruct | ~4.7 ГБ | **рекомендуемый старт** — потолок качества для этой задачи |
| Qwen2.5-14B-Instruct | ~9 ГБ | если хочется запаса под сложные фразы (условия, исключения) |
| Qwen2.5-32B-Instruct / Mistral Small | 14–20 ГБ | «максимально крутой», но делит VRAM с рендером |
| Qwen2.5-1.5B-Instruct | ~1 ГБ | fallback для слабой машины |

Модель — ПАРАМЕТР, не решение архитектуры: путь к GGUF в настройках, меняется без пересборки.
Список выше — по состоянию на май 2026; перед стартом свериться со свежими релизами.

## Где считать

**CPU по умолчанию.** Команда набирается руками раз в минуту, 1–3 секунды ответа никого не
убьют, зато ноль VRAM и ноль конкуренции с рендером. GPU-режим — опция в настройках для тех, кому
не жалко памяти: там ответ <100 мс, но во время инференса кадр просядает.

---

## E1. Граница: `EditorIntent`, а не «нейронка в редакторе»

Один интерфейс: строка → `EditorIntent { action, filter, quantifier, params }`. Реализаций две — `LlmIntent`
и `GrammarIntent`. Весь остальной редактор знает только про `EditorIntent` и не знает, откуда он взялся.
Это то, что позволяет выкинуть модель целиком и оставить фичу работать.

## E2. Рантайм инференса — ОТДЕЛЬНЫЙ ПРОЦЕСС

`llama-server` из llama.cpp, поднимается лениво при первом запросе, общение HTTP по localhost.

Почему не линковать в процесс:
* в движок не приезжает ни одной новой зависимости — ни в Release, ни в Release_Editor;
* падение или OOM в инференсе не роняет редактор с несохранённым уровнем;
* модель и рантайм обновляются отдельно от движка;
* секунда инференса делает цену IPC незаметной.

Запрос асинхронный, кадр не блокируется никогда. Модель в репозиторий НЕ кладётся — скрипт
скачивания в `tools/`, путь в настройках редактора.

## E3. Схема команд + GBNF: выдумать имя ФИЗИЧЕСКИ НЕЛЬЗЯ

Ответ ограничен **GBNF-грамматикой**: на каждом шаге сэмплинга разрешены только токены,
допустимые грамматикой. Это не «обычно валидный JSON», а гарантия.

**Главный ход шага: грамматика ГЕНЕРИРУЕТСЯ ИЗ УРОВНЯ** — в неё перечисляются ЛИТЕРАЛАМИ
реальные имена ассетов и допустимые действия. Галлюцинация несуществующего ассета становится
невозможной не по уговору, а по построению. Это тот же принцип, что и с барьерами: лучше
корректность по конструкции, чем проверка постфактум.

## E3.1. ТРИ ВЕТКИ ОТВЕТА: модель обязана уметь сказать «такого API нет»

Требование владельца, и оно вскрывает прямое противоречие в E3. Грамматика, перечисляющая
ТОЛЬКО существующие действия, делает честный отказ **физически невыразимым**: на запрос
«покрась все пальмы в красный» модель ОБЯЗАНА выбрать что-то из списка и подставит ближайшее —
например `bury`. Это ХУЖЕ галлюцинации: команда валидна, исполнима и не та.

Поэтому грамматика разрешает ТРИ формы ответа, и выбор между ними — часть задачи модели:

```
{"kind":"command",   "action":"bury", "filter":["coconut_palm","date_palm"], "scope":"all"}
{"kind":"needs_api", "requested":"покрасить в красный",
                     "proposed":"setBaseColor(objects, rgba)",
                     "why_existing_dont_fit":"setMaterial меняет весь материал, а нужен только цвет"}
{"kind":"unclear",   "question":"Какие именно деревья имеются в виду?"}
```

Структурные гарантии E3 при этом ЦЕЛЫ: внутри ветки `command` имена действий и ассетов
по-прежнему перечислены литералами и выдумать их нельзя. А `needs_api` — единственное место
со свободным текстом, и он НИЧЕГО НЕ ИСПОЛНЯЕТ по определению — его максимальный эффект
это строка в логе и текст на экране.

### Модель по умолчанию ХОЧЕТ УГОДИТЬ — это надо ломать явно

Главный риск здесь не технический, а поведенческий: instruct-модели обучены быть полезными и
почти всегда предпочтут «близкое действие» честному отказу. Значит в системном промпте
это переворачивается явно и жёстко:

* **`needs_api` ЛУЧШЕ, чем похожее действие.** Невыполненная команда стоит ничего,
  выполненная не та — порченный уровень.
* перед `needs_api` обязана перечислить, какие существующие действия рассмотрела и почему не подошли
  (поле `why_existing_dont_fit`) — это же страховка от ЛОЖНОГО отказа, когда API на самом деле есть;
* список действий в промпте идёт С ОПИСАНИЯМИ, а не одними именами: без них модель
  догадывается о семантике по названию и путает `bury` с «спрятать» (= `setEnabled(false)`).

### Запросы на API НАКАПЛИВАЮТСЯ — это готовый бэклог

Каждый `needs_api` пишется `LOG_INFO` в session-лог вместе с исходной фразой. Через неделю
работы это уже не диагностика, а список «что реально хотелось от редактора, отсортированный
по частоте» — ровно то, по чему стоит расширять API. В UI ответ показывается как
«Такого действия нет. Предлагается: `setBaseColor(objects, rgba)`» — без кнопки «выполнить»,
потому что выполнять нечего.

### Побочное следствие для архитектуры

Раз модель должна рассуждать о ГРАНИЦАХ API, список действий перестаёт быть захардкоженным
списком в промпте и становится **реестром в коде**: имя, описание, параметры, фабрика
`EditorCommand`. Из одного реестра генерируются и GBNF-грамматика, и описания в промпте, и
диспетчер исполнения. Добавление действия = одна запись в реестре, а не три правки в разных
местах, которые обязательно разъедутся.

## E4. Контекст в промпте и кэш prefill

Системный промпт: список действий, список ассетов уровня, типы, текущее выделение, примеры.
Он ПОСТОЯНЕН между запросами, а значит prefill кэшируется и каждый запрос — это десяток токенов
ввода плюс 20–40 токенов генерации. Перестраивается только при смене уровня.

## E5. Резолв селектора — уже существующий код

`intent.filter` → множество объектов через `MatchesSearch` (имя / тип / id / ассет) — тот же путь,
что у поиска в аутлайнере. Модель возвращает ИМЕНА АССЕТОВ, а не свободную строку, так что
никакой новой логики выборки писать не надо.

## E6. Исполнение: ПРЕДПРОСМОТР и только через CommandStack

Модель НИЧЕГО НЕ ИСПОЛНЯЕТ. Она возвращает намерение, UI показывает, что понялось и сколько
объектов зацепит: «Bury 247 objects — coconut_palm ×183, date_palm ×64. Выполнить?».
Дальше один `CompositeCommand` через `EditorCommandStack` — то есть Ctrl+Z откатывает ОДНИМ шагом.

Это не паранойя: за эту сессию буквальное понимание «все вершины под поверхностью» уже
утопило пальму на 15 метров. То же самое на 621 объекте без предпросмотра — потерянный уровень.

## E7. Грамматика как быстрый путь

Точные формулировки (`bury coconut_palm`, `delete selected`) разбираются без модели и отвечают
мгновенно. Модель подключается, только когда грамматика не справилась.

## E8. Гейты и деградация

* три конфига собираются БЕЗ модели и без llama.cpp на машине;
* модели нет → поле ввода **УБИРАЕТСЯ**, а не дизейблится (инертный контрол — врущий контрол);
* всё под `#if WITH_EDITOR`, в Release не остаётся ни байта;
* диагностика — `LOG_*` в session-лог (запрос, распознанный intent, число объектов, время), новых
  `logs/<name>.log` не заводить.

## Оценка

| шаг | объём |
|---|---|
| E1 + E5 + E6 (каркас, резолв, предпросмотр, undo) | 1 день |
| E2 + E3 + E4 (сервер, грамматика из уровня, промпт) | 1–2 дня |
| E7 + E8 (грамматика, гейты, UI) | 1 день |

## Чего здесь сознательно НЕТ

Нет «агента», который сам решает цепочки действий, нет доступа к файлам и ассетам, нет
генерации контента. Один шаг: фраза → одна команда редактора над выборкой объектов.
