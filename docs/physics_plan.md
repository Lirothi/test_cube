## 0. Правила

1. **Jolt за стеной.** `#include <Jolt/...>` только в `sources/physics/*.cpp`. Публичные `physics/*.h`, `pch.h` и
   остальной движок его не видят: обновление Jolt и смена его флагов трогают одну папку.
2. **Один источник позы.** Тело двигает объект только через `RenderableObject::SetRenderOffset`. Авторский трансформ
   меняет только явное Keep (PH3), поэтому сохранение уровня симуляцию не видит.
3. **Рендер про физику не знает.** Пассы, ресурсы, шейдеры и тени не меняются. На `RenderableObject` и `MeshManager`
   появляются только точки стыковки (регистрация, хуки, геттер, чтение геометрии). Если замер PH2 укажет на конкретный путь
   рендера, это отдельный шаг с согласия владельца, с GBV по правилам AGENTS.md.
4. **Физика живёт в игровой половине кадра.** Все вызовы Jolt — с игрового потока, в `Scene::Tick`, запросах редактора и
   MCP. Рендер получает только матрицу на передаче кадра (`Scene::Sync`). `--rt-audit` держит это правило.
5. **Что не движется, не платит.** Без активных тел `PhysicsSystem::Update` не вызывается вообще. Статические тела стоят
   памяти и времени загрузки, но не кадра. Обход сцены каждый кадр запрещён: реестр и очередь изменений, как у
   `OceanBuoyancy` (`OceanBuoyancy.h:36-37`).
6. **Настройка — у ассета.** `"collision"` в mesh.json, переопределение на объекте, у всего автоматическое значение.
   Поэтому мир работает без единой записи в `models/`. Запись в `models/` и `data/` — только словом владельца.
7. **Сначала простейшая модель.** Меш LOD0, выпуклая оболочка, примитив, родной пул потоков Jolt. Кэш форм, адаптер
   задач, асинхронный шаг — условные шаги PHa-PHd, только по замеру.
8. **MCP первым.** Всё, что смотрит на работающую физику или крутит её, идёт через открытый редактор. Чего нет —
   дописать, с кейсом в `TestMcpDrivesTheSameRoad` (`intent_regression.cpp:891`).
9. **Гейт сначала ломают.** У каждого гейта есть прогон, который обязан его уронить; без него тишина ничего не значит.

## 2. Что это даст и чего не даст

**Даст:** коллизию мира из тех же ассетов; падающие и лежащие предметы; в редакторе «уронить и оставить как легло»; ходьбу
по острову с упором в стены; предметы на воде; быстрые лучи по земле.

**Не даст и не планируется:** разрушения, ткань и soft body (нужен деформируемый BLAS), ragdoll (нет скелетов), машины,
GPU-вычисления и волосы Jolt 5.6, выпуклая декомпозиция (в Jolt её нет). Листва и ветер остаются на GPU: лист не сталкивается.

**Цели (предложение, владелец поправит; не замеры):**

| Что | Цель |
|---|---|
| Уровень, где ничего не движется | кадр и картинка неотличимы от пола шума |
| wind_test, смена уровня | прирост не больше 30 мс к ~155 мс (`game_thread_plan.md` §G10d) |
| Память статического мира wind_test | известна и в `mem:`; порог решает владелец |
| 100 активных тел | шаг не дольше 0,3 мс игровой половины, рендер-строки растут не больше 0,2 мс в сумме |

Шаг фиксированный: 60 Гц, один collision step (по `Architecture`, в этом режиме система устойчива), не больше

### 3.3 Координаты: числа передаются как есть

Jolt описан как правосторонний Y-up, мы левосторонние Y-up (`LookAtLH`). Конвертация **не нужна**:

- Формулы Jolt не знают о руке: векторные произведения и повороты те же. Зеркальный мир — та же физика, а числа те же.
- Лицо треугольника: у нас по часовой (AGENTS.md, «Handedness»), у Jolt против часовой (сверить). В своих системах оба дают
  одно и то же `(b - a) x (c - a)` наружу, поэтому индексы идут в исходном порядке. Прочитанные страницы про порядок вершин
  молчат, это решает гейт `TestPhysicsPose`.
- Кватернион: `Math::quat` (`XMQuaternion`, `Math.h:189`) и `JPH::Quat` — `x, y, z, w` одной формулы `q v q*`, а
  `XMMatrixRotationQuaternion` (`Math.h:275`) для вектора-строки `v * M` даёт тот же поворот. **Матрицы через границу не
  ходят** (у Jolt столбцы, у нас строки), только позиция и кватернион.
- Гравитация задаётся явно: `SetGravity(0, physics.gravity, 0)`, `-9.81`. Значение по умолчанию на страницах не указано.

От позы к смещению: тело создано в `(T0, q0)` авторских, без масштаба. Модель должна стать `S * R(t) * T(t)`, а
`M = S * R0 * T0 * offset`, значит `offset = inverse(R0 * T0) * R(t) * T(t)`. Позицию брать `GetPositionAndRotation`, а не центр
масс: форма сама центрируется по центру масс (`Architecture`), и путаница даст сдвиг на смещение центра масс.

Float хватает: остров в пределах 200 м от начала координат, а Jolt стабилен примерно до 5 км.

### 3.4 Данные

mesh.json, всё необязательно:

```jsonc
"collision": {
  "shape": "auto",            // auto | mesh | hull | box | sphere | capsule | none
  "lod": 0,                   // для mesh и hull
  "excludeSlots": [1, 3],     // по умолчанию: слоты с windFoliage > 0
  "density": 1000,            // кг/м3; mass > 0 важнее
  "mass": 0,
  "friction": 0.5,
  "restitution": 0.1,
  "convexRadius": -1          // -1 = автоматически, §6
}
```

Объект уровня: `"physics": "none" | "static" | "dynamic"`, отсутствие = `static`, ключ пишется только не по умолчанию.
`"collision"` на объекте переопределяет ассет (это даёт `ResolveMeshAsset`). `"buoyant": true` без `dynamic` = кинематика.

Только `staticMesh` (в нём и остров). `instancedModels`, `transparentMesh`, частицы и океан в мир не входят.
Объект с `enabled: false` (и `SetVisible(false)`) тела не имеет.

### 3.5 Форма по умолчанию (`shape: auto`)

| Объект | Форма | Почему |
|---|---|---|
| Нет твёрдых слотов (23 ассета) | нет тела | только листва |
| `static` | `MeshShape` по LOD0 без листвы, общий на ассет + `ScaledShape` на объекте | «Complex as simple». Статика не считает инерцию, а предмет лежит ровно на видимом песке |
| Кинематика (лодка) | то же | Jolt разрешает кинематический меш; динамика в лодке сталкивается с её реальной формой |
| `dynamic` | `ConvexHullShape` по вершинам LOD0 без листвы; масштаб через `Shape::ScaleShape` | столкновение меша с мешем Jolt запрещает, а динамические меши советует избегать |
| Сборка оболочки не удалась | бокс по границам, `LOG_WARNING` | объект должен падать, а не исчезать |

Неравномерный масштаб: проверять `Shape::IsValidScale`, при отказе `MakeScaleValid` и `LOG_WARNING_ONCE_PER_MESSAGE`.

| Игровой поток | Всё. `Update` блокирует его до конца шага |
| Потоки Jolt | Только внутри `Update`. Листенеры идут с нескольких потоков и только читают тела (`Architecture`); на PH2 их не ставим |
| Поток рендера | Jolt не видит, берёт матрицу на `Sync` |
| Любой поток (загрузка) | Только `physics::Register/Unregister`: кладут в очередь, тела не трогают |

Запрос во время `Update` невозможен: `Update` и запросы редактора идут на одном потоке.

**Асинхронная загрузка** (`game_thread_plan.md:987`, строка `:1007`): реестр физики — того же класса, что `OceanBuoyancy::Register`,
регистрируется при подмене. `AddBodiesPrepare` разрешён с фонового потока, `AddBodiesFinalize` атомарен: на подмене.

### 3.7 Режимы

| Режим | Когда | Что |
|---|---|---|
| Edit | Редактор открыт, `physics.simulate` 0 | Тела на авторских позах, шага нет, запросы работают, смещения сняты |
| Simulate | Кнопка / `physics.simulate:1` | Шаг идёт; правка трансформа сажает тело туда, куда поставили (как `OceanBuoyancy.h:29-30`) |
| Runtime | Сборка или запуск без редактора | Simulate с загрузки уровня |

**Stop:** тела на авторские позы, скорости 0, `ClearRenderOffset` и сброс истории движения на ближайшей передаче. Для этого нужен
флаг на объекте: `ResetMotionHistory` с игрового потока писал бы то, что читает рендер, а без сброса скачок даст один кадр огромного
motion vector, и DLSS размажет предмет. **Keep:** см. PH3.

## 8. Исполнителю

- Сборка — три команды из `docs/game_thread_plan.md` §8, байт в байт; Debug первым. `third_party_physics` собирается через ProjectReference.
- Гейты: Debug-сборка `test_cube.vcxproj`, затем `tools/intent_regression.vcxproj` (он читает её tlog).
- Новые файлы движка — в `test_cube.vcxproj` **и** `.filters`. Исходники и этот файл CRLF, проверять байтами (AGENTS.md, «Line Endings»).
- `python tools/check_logging.py` перед коммитом. Никаких `printf` и новых `logs/<name>.log`: вердикты гейтов — строками `LOG_*`.
- `dynamic_cast` не использовать: у `RenderableObjectBase` есть `AsRenderableObject()`.
- Вход в живую проверку: `--editor --level=...`, MCP на `127.0.0.1:8128`, в начале серии `reset_settings`. Ручки физики в нём не сбрасываются:
  называть их в каждом плече. Процесс редактора убивать по своему PID, не закрывать: случайный Save недопустим.
- Замер: F2 закрыт, камера настоящая, чередование плеч, два прохода, пол шума измерить первым. Режим рендера по умолчанию (поток рендера
  включён), гейт, задевающий порядок кадра, — ещё и `--set=frame.renderThread:0`.
- Коммит — только по просьбе владельца, сообщение одной строкой. Ассеты, уровни и настройки владельца не трогать и не коммитить.

### 9.3 Что нашлось по дороге

**Старый баг VSM, не физика: тени пропадали целыми страницами** (`VirtualShadowMap.cpp`, `EnsureRenderResources`). Владелец заметил прямоугольные светлые пятна в тени пальм прямо в первом стрессе.
`renderCasters_` хранил число элементов (объекты × 4 LOD), а сравнивался с числом объектов, поэтому `VSM.PageVisibleList` не рос, пока объектов не станет вчетверо больше, чем при загрузке.
Записи пар для старших физических страниц пула уходили за конец буфера, UAV их отбрасывал, и страница рисовала пустоту. Судя по коду, тот же эффект без физики даёт переход на уровень крупнее или массовый `place`; отдельно это не проверялось.

|---|---|---|

| 200 | 5,4 % | |
| 500 | 7,6 % | |

`tessy.vsm:0`, `tessy.lod:0`, `vsm.hzbCull:0` и `vsm.pageCaching:0` картину не меняли: это и подсказало, что дело в общем списке. Счётчики потерь (`clustersLost`, `runsLost`, `refused`) молчали, потому что записи теряются ниже их.
Новых GPU-ресурсов и дескрипторов нет, поэтому GBV не гонялся. Список теперь растёт с запасом в четверть; первое создание — точно по размеру, без добавки VRAM.

**Тела проваливались сквозь мир.** У меша нет толщины: кокос, упавший с 14 м, проходит за шаг 27 см при радиусе 13 см. 6 кокосов из 30 падали вечно со скоростью 180 м/с, держа мир бодрствующим. Из 2000 после 25 с не спали 1613. С `LinearCast` у всех — 0 упавших и 436 бодрствующих в тот же момент. Цена: шаг кучи при посадке 3,2 -> 6,9 мс на 2000 тел, падение 0,66 -> 0,87 мс, на 100 телах в пределах разброса.
