## 2. Что делает UE (сводка)

### 2.1 Офлайн: кластеры и DAG (`Source/Developer/NaniteBuilder/Private`)

- **Кластер**: ≤ 128 треугольников, ≤ 256 вершин (`Shaders/Shared/NaniteDefinitions.h:21-25`, сверено). Разбиение
  — METIS рекурсивной бисекцией, окно 124-128 (`ClusterDAG.cpp:135`; `GraphPartitioner.cpp:126-186`). Граф —
  треугольники, смежность по ПОЗИЦИЯМ (швы UV/нормалей граф не режут), вес общего ребра 260
  (`ClusterDAG.cpp:42-72,163`), плюс «локальные» связи между островами по Morton-порядку (вес 1). Лимит вершин
  применяется позже: кластер > 256 вершин делится пополам (`Encode/NaniteEncodeConstrain.cpp:286-298`). Кластер
  может нести до 64 материалов, треугольники сортируются по диапазонам материалов (`Cluster.cpp:2245-2283`).
- **Группы**: 8-32 кластера (`ClusterDAG.cpp:727-728`, сверено). Граф групп — кластеры, вес = общие рёбра × 12
  (соседи из одной породившей группы) или × 16, + 4 (`:811-813`).
- **Упрощение группы**: внешние рёбра группы ЗАПИРАЮТСЯ (`LockPosition`, `Cluster.cpp:1023-1040`; штраф 1e8,
  `MeshSimplify.h:73`), открытые края меша — нет. Родителей у группы `ceil(tris / 256)`, цель
  `родители × 126` треугольников (≈ половина, `ClusterDAG.cpp:730-748, 1467-1470`, сверено); упрощённая группа заново
  режется на кластеры. Если вышло больше родителей — цель −2 треугольника и заново (`:1556-1584`).
- **Ошибка и монотонность**: у листа `LODError = 0`, `LODBounds` = сфера кластера (`Cluster.cpp:1413-1414`). Группа:
  `ParentLODError = max(LODError детей, ошибка упрощения)`, `LODBounds` = сфера вокруг сфер детей
  (`ClusterDAG.cpp:1438-1446, 1587`); родители копируют это себе. Корень — `ParentLODError = 1e10` (`:1295-1303`).
  Ошибка — `sqrt(макс. квадрика) / PositionScale`, в единицах объекта (`Cluster.cpp:1107`).
- **Иерархия**: 4-арный BVH по «частям групп» (`NANITE_MAX_BVH_NODE_FANOUT_BITS 2`, `NaniteDefinitions.h:103-105`),
  отдельное дерево на mip-уровень + цепочка корней (`Encode/NaniteEncodeHierarchy.cpp:333-501, 798-820`). Узел хранит
  на каждого ребёнка: `LODBounds`, AABB, `MinLODError`, `MaxParentLODError`, ссылку на детей
  (`Runtime/Engine/Public/Rendering/NaniteResources.h:57-82`).
- **Запасной меш** (RT и не-Nanite пути): «разрез» DAG по ошибке (`ClusterDAG.cpp:1607-1745`), 1 % ошибки от
  размера, для RT-прокси 2 % (`NaniteBuilder.cpp:395-415, 779-787`).
- **Упаковка**: квантование позиций, октаэдрические нормали, полосы индексов, страницы стриминга 128 КБ
  (`Encode/*`). **Нам не нужна** — VRAM хватает, данные храним несжатыми (§7).

### 2.2 Рантайм: отсечение, LOD, растеризация (`Shaders/Private/Nanite`, `Renderer/Private/Nanite`)

- **Порядок**: инстансы → узлы иерархии (многопроходно: одна непрямая диспетчеризация на уровень, персистентные
  потоки ВЫКЛЮЧЕНЫ по умолчанию — «not recommended for non-fixed hardware», `NaniteCullRaster.cpp:322-328`, сверено) →
  кластеры → бининг растеризации → HW и SW растеризация (`NaniteCullRaster.cpp:4586-4623, 6970-7083`).
- **Два прохода окклюзии**: main — против HZB прошлого кадра, прошлые матрицы; отсечённое копится и в post-проходе
  перепроверяется против HZB, построенного из глубины main (`NaniteCullingCommon.ush:619-661`;
  `NaniteInstanceCulling.usf:169-175`; `NaniteClusterCulling.usf:501-507, 941-962`). У нас для инстансов это уже есть
  (occlusion plan S4/S5).
- **LOD**: `LODScale = 0.5 · P[1][1] · ViewHeight / r.Nanite.MaxPixelsPerEdge` (по умолчанию 1)
  (`NaniteShared.cpp:197-199`, сверено). Узел: спускаться, если `EdgeScale.min ≤ LODScale · UniformScale ·
  MaxParentLODError`; лист пропускается, если `EdgeScale.max < LODScale · MinLODError`
  (`NaniteClusterCulling.usf:258-285`). Кластер: рисовать, если `EdgeScale.min > LODScale · UniformScale · LODError`
  (`:287-299`). `EdgeScale` — min/max (Z · cosθ) по сфере `LODBounds`, ортопроекция = 1
  (`NaniteCullingCommon.ush:112-159`).
- **HW или SW**: HW, если самое длинное ребро кластера > 32 пикселей (`r.Nanite.MinPixelsPerEdgeHW`) или кластеру
  нужен клиппинг (`NaniteClusterCulling.usf:300-309`, сверено). HW: mesh shader, иначе primitive shader, иначе
  **обычный VS**: `DrawInstanced(128 · 3, число кластеров)`, кластер из `SV_InstanceID`, треугольник из
  `SV_VertexID / 3`, индексы декодируются из данных кластера, **индексный буфер не строится**
  (`NaniteRasterizer.usf:3161-3222`, сверено). SW: compute, 64-битный `InterlockedMax` в visibility buffer
  (глубина | кластер | треугольник), для теней — 32-битный по глубине (`NaniteWritePixel.ush:20-35`).
- **Маски и WPO**: «программируемая растеризация» по бинам материалов; альфа-тест в PS (HW) или в растеризаторе (SW);
  WPO в вершинах; боксы узлов и кластеров (не сферы LOD) расширяются на `MaxWPOExtent`
  (`NaniteClusterCulling.usf:160-169`; `NaniteRasterBinning.usf:600-800`).

### 2.3 Nanite в VSM (`Shaders/Private/VirtualShadowMaps`, `Renderer/Private/VirtualShadowMaps`)

- Вид на уровень клипмапы (без mip), у локальных — вид на грань с mip; каждый вид 16384² = 128×128 страниц
  (`VirtualShadowMapArray.cpp:4948-5105`).
- **Тест страниц на всех уровнях** — инстанс, узел, кластер: прямоугольник в страницах, флаги страниц
  (запрошена / не закэширована / static / dynamic), опционально маска приёмников 8×8 на страницу
  (`VirtualShadowMapPageOverlap.ush:59-205`). HZB VSM — через таблицу страниц в физический HZB
  (`:224-321`).
- **Кластер выдаётся по окнам страниц**: 4×4 страницы для HW, 8×8 для SW; один «видимый кластер» на непустое окно
  (`NaniteClusterCulling.usf:877-936`, сверено). Запись — `InterlockedMax` в пул; HW-путь сдвигает клип-пространство
  и переводит пиксель через таблицу страниц в PS (`NaniteRasterizer.usf:2650-2654, 3342-3354`).
- **Кэш**: WPO-кастеры никогда не кэшируются как static и пачкают каждую страницу, которой касаются, каждый кадр
  (`VirtualShadowMapPageCacheCommon.ush:11-21`) — ровно наш случай с ветром. Отсечение WPO по уровню клипмапы:
  `r.Shadow.Virtual.Clipmap.WPODisableDistance` / `.LodBias` = 1 / 3 (`VirtualShadowMapClipmap.cpp:99-112, 415-421`).
- **LOD в тенях**: `r.Shadow.NaniteLODBias = 1` (сверено) → `MaxPixelsPerEdge` ×2 в тенях; клипмапы
  ортографические — один срез LOD на уровень.

## 4. Решения

1. **Порядок по выгоде, не по UE.** UE строит DAG, потому что его цель — непрерывный LOD для плотных мешей. Наша
   измеренная потеря — гранулярность отсечения VSM. Поэтому сначала **кластеры поверх существующих LOD** (N1-N3),
   DAG — позже и по желанию (N7).
2. **Кластер = непрерывный диапазон существующего индексного буфера.** В запекании треугольники каждого
   (LOD × сабмеш) переупорядочиваются по кластерам (`meshopt_buildMeshlets`, 128 треугольников / 256 вершин как в
   UE), и кластер — это `(firstIndex, triCount)` в том же IB. Все старые пути (G-buffer, атласы, RT) рисуют те же
   диапазоны, просто в другом порядке треугольников. Сжатие UE не нужно.
3. **Растеризация — VS-путь UE первым** (`NaniteRasterizer.usf:3161`): `DrawInstanced(128 · 3, кластеры)`, индекс
   вершины = `MegaIB[cluster.first + SV_VertexID]`, треугольник за пределом кластера — вырожденный. Не нужны ни mesh
   shader'ы, ни новый тип PSO, ни новая сигнатура `ExecuteIndirect`; GBV его видит. Mesh shader — оптимизация
   (повторное использование вершин), фаза N6, A/B.
4. **Без visibility buffer и SW-растеризатора** до N8: глубина в пул VSM пишется аппаратно, как сейчас (вьюпорт
   страницы + `SV_ClipDistance`). SW окупается на микротреугольниках, которых в наших ассетах нет (пальма 1-10 тыс.
   треугольников).
5. **Отсечение кластеров — compute между setup и raster**, на парах (страница × кастер), которые уже собирает scatter:
   каждая пара перебирает кластеры своего (группа × LOD), бокс кластера (расширенный на ветер) проверяется против
   плоскостей страницы — тот же тест, что в `vsm_page_setup_cs` для инстансов. Окна страниц UE (4×4) — позже, если
   пары станут узким местом.
6. **Ветер**: бокс кастера сейчас на ветер НЕ расширен — намеренно (`ShadowGpuData::FillBounds`: расширение по всем
   осям на худший случай, ~3 м на wind_test, стоило `Pass_VsmPageRender` ×2,5). Пока меш рисовался в страницу
   целиком, это прощалось. Бокс кластера в разы меньше, и качнувшийся край кроны уйдёт в соседнюю страницу, где кластер
   не нарисован, — дыра в тени. Поэтому бокс кластера расширяется на максимальное смещение ветром, как UE на
   `MaxWPOExtent` (`NaniteClusterCulling.usf:160-169`), — **направленно** (по ветру по XZ + немного по Y, как советует
   тот же комментарий), считается при загрузке уровня. Правила перерисовки страниц VSM не меняются (UE: WPO пачкает
   страницы каждый кадр).
7. **Переключение на лету — устройство** (правило §0.2):
   - **Данные строятся всегда, ручка выбирает путь.** Таблица кластеров — часть кастер-сета
     (`ShadowGpuData::Rebuild`) и строится при любом значении ручек. Переключение не вызывает `Rebuild`, не ждёт GPU
     и ничего не выделяет. Цена — память таблицы, порядка мегабайта (~32 байта на кластер, кластер = 128
     треугольников); посчитать в N2 и вывести в `mem:`.
   - **Оба PSO создаются при Init** (`VSM_PAGE` и `VSM_TESSY`; в N6 VS и MS), как выключенный `castShadow` строит
     свои теневые PSO. Первое переключение — без хитча компиляции; блобы лежат в кэше PSO.
   - **Значение фиксируется в снимке кадра** (`SceneFrameData`, как `rtCutoutOpacityOverride`), и все проходы кадра
     читают его оттуда, не из глобала. Cull и raster одного кадра никогда не расходятся. Иначе кадр, где cull уже
     записал кластеры, а raster ещё читает args пар, — кадр без теней.
   - **Ресурс, который ручка ОСВОБОЖДАЕТ** (данные DAG в N7, visibility buffer в N8), освобождается только в точке
     согласования резидентности с ожиданием GPU (`Scene::ReconcileShadowMode`). Покадровый код только спрашивает,
     есть ли ресурс и того ли размера (`[[runtime-knob-frees-resource]]`). Обе стороны резидентности — в лог.
   - **Переключение пачкает кэш страниц VSM один раз** (как `casterLodsChanged_`): глубина обязана совпасть, но
     замер после переключения иначе меряет не тот кадр. Временные истории (DLSS, SkyVis, GI) не сбрасываются: кадр тот
     же. HZB строится из глубины кадра, каким бы путём она ни нарисована, поэтому двухпроходному отсечению кластеров
     (N5) разогрев после включения не нужен.
   - **Проектные ручки**, как `gi.*` / `skyVis.*`: сохраняются в `graphics_settings.json`, `reset_settings` их не
     трогает. Каждое плечо A/B называет их явно (AGENTS.md: оставленная ручка испортила день замеров 2026-10-26).
   - **Нет поддержки железа** (mesh shader tier в N6, RT для N8 не нужен): `tessy.raster:ms` откатывается на `vs`,
     Warning один раз, в Developer Controls контрол выключен с причиной.
   - **Гейт переключения в каждой фазе**: `--sweep=<ручка>:1,0,1,0,1,0` с `--shot` на каждом значении (один процесс,
     шесть переключений тем же диспетчером, что `--set`): снимки «1» и «0» попарно совпадают до шумового пола, нет
     `Removing Device`, строка `mem:` ровная (нет роста от переключений). Живьём: 20 переключений через MCP с
     `screenshot {burst: 30}` вокруг каждого — ни одного кадра без теней на переключении.
8. **Каждый меш поддерживает оба пути** (владелец, 2026-10-28: «сделай, чтобы меши поддерживали оба пути»):
   - **Меш с кластерами рисуется обоими путями** из одних данных: классический путь берёт диапазоны LOD в IB, как
     сейчас; кластерный — таблицу кластеров поверх того же IB (§4.2). Никакого второго IB и никакой второй копии
     вершин.
   - **Меш без кластеров остаётся на классическом пути** при любом значении ручек, в том же кадре, где остальные идут
     кластерами. Решение принимается на группу кастер-сета (`ShadowGpuData`, группа = меш × LOD): у группы есть
     кластеры → пары (страница × кастер) уходят в кластерный cull; нет → классические args, как сегодня. Сцена бывает
     смешанной, и это штатный случай, а не деградация.
   - **Загрузчик читает v3 и v4.** Проверка версии в `ReadMeshBinary` (`MeshManager.cpp:735`) и в проверке
     свежести (`:1365`) становится диапазоном `kMeshBinMinVersion..kMeshBinVersion`: бин v3 грузится как сейчас,
     только без таблицы кластеров. Запекание пишет только v4. Значит, переход на v4 никого не ломает, и перепечка
     идёт по ассетам (с самых дорогих в тенях — пальмы, ванная), а не обязательной массовой операцией.
   - **Меш, разобранный при загрузке** (нет `.bin`: `GenerateLods`, OBJ), строит кластеры при загрузке тем же кодом,
     что запекание (`meshopt_buildMeshlets` дешевле генерации LOD, которая там уже идёт). Без кластеров остаются
     только бины v3.
   - **Видно, кто на каком пути**: Developer Controls > VSM и строка `[VSM]` — «кластерами N из M групп», плюс
     список ассетов без кластеров (раз за загрузку уровня, Info). Иначе неперепечённый ассет молча меряется
     классическим путём, и A/B врёт.
   - **Гейт смешанной сцены**: wind_test, где одна пальма перепечена в v4, а остальные остались v3: кадр с
     `tessy.vsm:1` совпадает с `tessy.vsm:0` до шумового пола, счётчик показывает ровно эту пальму.

  как основа для N7 и плотных ассетов.
- `tessy.gbuffer:0|1`. Скорости (`prevWorld`) — по инстансам и от пути не зависят; HZB прошлого кадра есть при
  любом пути (§4.7), так что переключение не даёт ни кадра без отсечения, ни скачка скоростей для DLSS. Гейт
  переключения §4.7 плюс пролёт (`camera.fly`) с переключением посреди burst.

### N6. Mesh shader (≈ 1 неделя)

- RHI: `D3D12_OPTIONS7.MeshShaderTier`; профили `ms_6_5` / `as_6_5` в `Material.cpp`; PSO через
  `ID3D12Device2::CreatePipelineState` (поток подобъектов) + кэш PSO (блоб работает так же); сигнатура
  `ExecuteIndirect` `D3D12_INDIRECT_ARGUMENT_TYPE_DISPATCH_MESH`.
- Mesh shader: группа = кластер, ≤ 256 вершин / 128 примитивов (`NaniteRasterizer.usf:3024-3155`), вершины
  считаются один раз (VS-путь — трижды на треугольник).
- `tessy.raster:vs|ms`, A/B на трёх видах, гейт переключения §4.7. Без `MeshShaderTier` — откат на `vs` (§4.7).
  GBV с mesh shader'ом проверить самотестом до доверия.

### N7. DAG — непрерывный LOD (3-4 недели, по Q3)

- UE-референс: весь §2.1. Сборщик: `meshopt_buildMeshlets` (листья) → `meshopt_partitionClusters` (группы 8-32) →
  `meshopt_simplifyWithAttributes` с `vertex_lock` на внешних рёбрах группы (НЕ `LockBorder` — он запирает и
  открытые края, UE их не запирает), `ErrorAbsolute` (ошибка в метрах объекта), цель `ceil(tris / 256) · 126` →
  повторная нарезка; максимум ошибки и сфер вверх по DAG; 4-арный BVH по группам на mip-уровень. Самим писать: цикл
  DAG с повтором, учёт внешних рёбер, монотонность, BVH, разрез для запасного меша (RT и старые пути).
- Рантайм: обход BVH многопроходно (уровень = диспетчеризация, как UE по умолчанию), формулы LOD §2.2 в НАШИХ
  единицах: `LODScale = 0.5 · W · P[0][0] / pixelError` — тот же множитель, что `LodSelect.h` уже берёт с ЭТОГО
  кадра; `lod.pixelError` (1) = `MaxPixelsPerEdge`. Тени — `×2` (как `r.Shadow.NaniteLODBias = 1`).
- **Два уровня включения.** `"tessyLod": true` в mesh.json решает, ЗАПЕКАЕТСЯ ли DAG для ассета
  (`[[per-asset-not-global-class]]`, перепечка этого ассета). Живая ручка `tessy.lod:0|1` решает, ИСПОЛЬЗУЕТСЯ ли он.
  Дискретные LOD остаются в `.mesh.bin` рядом с DAG, поэтому `tessy.lod:0` — ровно сегодняшний выбор LOD
  (`LodSelect.h`), а не разрез DAG. Цена — память: DAG ≈ 2× кластеров LOD0 сверх дискретных LOD, посчитать на
  пальмах. RT остаётся на BLAS из LOD0 при любом значении: переключение BLAS не перестраивает.
- Гейт: нет «попов» LOD при пролёте (`camera.fly`, burst-снимки), бюджет треугольников G-buffer ≤ дискретного LOD,
  гейт переключения §4.7 (здесь снимки «1» и «0» РАЗНЫЕ по построению — сравнивать попарно «1» с «1», «0» с «0»).

### N8. Visibility buffer, SW-растеризатор, стриминг (2-3 месяца, только при плотных ассетах)

- `NaniteRasterizer.usf:429-883`, `NaniteWritePixel.ush`, `NaniteShadeBinning.usf`, стриминг страниц. Не начинать без
  ассетов, которые его требуют (сотни тысяч треугольников на объект).
- `tessy.visBuffer:0|1`: буфер видимости и бины шейдинга выделяются и освобождаются только в точке согласования
  резидентности (§4.7), G-buffer-путь остаётся рядом.

## 6. Риски

- **Вырожденные треугольники VS-пути**: при 128 · 3 вершин на кластер короткий кластер тратит VS на пустые. UE мирится
  с этим; если окажется заметно — бинить кластеры по размеру (2 сигнатуры) или N6.
- **Число пар** (страница × кастер) в роще — оценка ~4 тыс. (20,7 млн / ~5 тыс. треугольников на кастер; посчитать в
  N0 счётчиком); поток на (пару × кластер) — до ~300 тыс.; если cull станет дороже 0,1 мс — окна страниц UE (4×4)
  вместо пар.
- **Ветер и бокс кластера**: недорасширенный бокс = дыра в тени качающейся кроны (у кастера бокс не расширен
  намеренно — §4.6). Расширение кластера стоит дешевле: бокс мал, лишних страниц немного; мерить вход треугольников
  с расширением и без, дыры — burst-снимками на ветру.
- **Порядок треугольников (N1)** меняет порядок прорисовки альфа-тестовых листьев — глубина та же, но если где-то есть
  смешивание по порядку (стекло?), сравнить снимки.
- **Перепечка ассетов (N1)** — по ассетам, v3 рядом продолжает работать (§4.8); бэкап `.mesh.bin` перед каждой
  (`[[manifest-must-describe-its-bake]]`). Риск — забытый неперепечённый ассет, меряемый классическим путём:
  счётчик §4.8 его показывает.

## 7. Отступления от UE

| UE | Мы | Почему |
|---|---|---|
| DAG сразу | кластеры поверх дискретных LOD (N1-N6), DAG в N7 | измеренная потеря — гранулярность VSM, а не LOD |
| METIS, смежность по позициям | `meshopt_buildMeshletsSpatial` (SAH, 32-128 треугольников, 256 вершин) | уже в проекте; для отсечения по страницам важен размер бокса: на пальме полудиагональ 0,78 м против 0,86 у `meshopt_buildMeshlets` (TestTessyClusters); в N7 пересмотреть |
| бокс кластера + `MaxWPOExtent` (изотропно, на материал) | интервальная оценка изгиба ветром по осям, с этим кадром (§9) | WPO у нас один и известен формулой; изотропная оценка пускала ×2 кластеров |
| сжатые страницы кластеров | кластер = диапазон существующего IB | VRAM хватает, старые пути не трогаются |
| mesh / primitive shader первым | VS-путь первым, MS в N6 | без новых PSO и сигнатур; GBV |
| MS-группа = кластер, ≤ 256 вершин (`NaniteRasterizer.usf:3024-3155`) | MS-группа = мешлет ≤ 64 вершин, 64 потока; кластер режется на мешлеты при загрузке | при 256 × 52 Б объявленного выхода MS медленнее VS-пути (занятость SM); 64 — быстрее всех замеренных (§9) |
| visibility buffer + SW raster | аппаратная глубина в пул / G-buffer | микротреугольников нет |
| окна 4×4 страницы | пары (страница × кастер) от нашего scatter | пары уже есть; окна — если cull станет узким |
| длины в см | метры | `[[ue-lengths-are-cm]]` |
